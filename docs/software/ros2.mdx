In the Apex architecture, the robot's onboard controller runs the ROS 2 nodes for robot control, teleoperation, cameras, and recording: a Tianzhun or Lingjing Thor controller on current robots, or an Orin on earlier ones. Apex Teleop on the host PC manages the connection and the operator workflow.

## Interface references

| Robot or device | Reference |
| --- | --- |
| Marvin Pro | [Marvin Pro ROS 2 interfaces](./ros2-marvin-pro.mdx): namespace, safety rules, input arbitration, topics, services, network ports, and topic rates |
| Skye and Luna | [Skye and Luna ROS 2 interfaces](./ros2-skye-luna.mdx): joint differences, whole-body commands, services, and the mobile base |
| Head and wrist cameras | [Camera ROS topics](./cameras.mdx#ros-topics) |
| RealSense cameras | [RealSense cameras (ROS 2)](./realsense.mdx) |
| Topics allowed for recording and forwarding | [Topic whitelist](../teleoperation/advanced/topic-whitelist.mdx) |

Confirm topic names, message types, units, frames, and update behavior on your installed release before writing a client. The output of `ros2 topic list -t` on the robot is authoritative.

## Load the Apex ROS 2 environment

Log in to the robot's controller (see [Connect to the Orin or Thor](./cameras-firmware.mdx#connect-to-the-orin-or-thor)) and load the environment in every new terminal:

```bash
source /etc/apex/apex_ros_env.sh
```

On Marvin Pro, Apex nodes run in the `tj` namespace by default, so core interfaces are under `/tj/...`. Applications written for the older `/control/...` and `/info/...` paths need updating.

## Keep interfaces distinct

| Interface | Role |
| --- | --- |
| Marvin motion SDK | Communication with the robot controller |
| Apex ROS 2 interfaces | Robot-side application integration and telemetry |
| Apex desktop application | Operator connection, mode selection, and recording |

ROS 2 integration does not imply that every SDK function is exposed as a topic or service. Do not assume Luna/Skye message definitions or controller settings apply to Marvin Pro.

## Before sending commands

Confirm which process owns robot control, how control is handed over, and which coordinate frame and units the command uses. Read the safety requirements and input arbitration rules in the interface reference for your robot, and [Operation modes and input sources](../teleoperation/operation-modes.mdx).
