Complete the [hardware connections](./wiring.mdx) and choose the [matching software](./compatibility.mdx) first. This procedure establishes communication and reads status; it does not command motion.

## Connect Marvin Platform

[![Marvin Platform connected to a robot: IP address (1), Connect Robot / Disconnect (2), Connected indicator (3), arm status fields (4), controller and SDK versions (5)](/img/marvin-pro/marvin-platform-connected.webp)](pathname:///img/marvin-pro/marvin-platform-connected.webp)

1. Start the Marvin Platform version supplied for your controller. If it isn't installed yet, see [Install Marvin Platform](../software/install-marvin-platform.mdx).
2. Connect the computer to the integrated control box and give it an address on the robot's `6.6.7.x` network. See [Connect your PC](../software/connect-pc.mdx).
3. Enter the motion controller's IP <span className="ui-marker">1</span>, `6.6.7.190` by default.
4. Click **Connect Robot** <span className="ui-marker">2</span>. Once feedback is arriving, the button changes to **Disconnect** and the indicator in the top bar reads **Connected** <span className="ui-marker">3</span>.

The September software guide's example address, `192.168.1.190`, belongs to the standalone Marvin arm controller. If your unit was configured with a different address, use the one recorded for it.

## Confirm live feedback

UDP communication doesn't return a connection-success flag, so Marvin Platform shows **Connected** only after fresh feedback frames arrive from the controller. If it doesn't, see [If the connection fails](#if-the-connection-fails). A stationary arm's positions may not change; don't command motion just to test the connection.

Check the status fields <span className="ui-marker">4</span> on the left of each arm's panel, for both arms:

- **Status** is the arm's current mode, using the numbers in [Control modes](../software/control-modes.mdx). In the screenshot, both arms are enabled in Position mode (`1`).
- For disabled, stationary arms, the manual describes **Status** `0`, **Drag** `0`, **LowSpeed** `1`, and **ArmError** `0`.
- A non-zero **ArmError** is an error code. See [Troubleshooting](../support/troubleshooting.mdx).

The bar at the bottom of the window <span className="ui-marker">5</span> shows the controller version and the SDK version, for example `100343024`. Include both when you contact Gento support.

## If the connection fails

Check power, Ethernet connections, the configured controller IP, host network settings, and the firewall. If the controller was just updated to firmware 1004, check that its cables are on the new ports; see [After the 1004 firmware update](../software/connect-pc.mdx#after-the-1004-firmware-update). [Connect your PC](../software/connect-pc.mdx) has a troubleshooting table. For the SDK family in the Pro V1.0 manual, the documented UDP port range is `50000–50010`; verify it against your installed package before changing firewall rules.
